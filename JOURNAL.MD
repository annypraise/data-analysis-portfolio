Why I Want to Become a Data Analyst

I want to become a Data Analyst because I enjoy working with information, solving problems, and using data to understand what is happening and make better decisions. I believe data analysis is a valuable skill that can be applied across many industries, including business, research, healthcare, development, and humanitarian work. Becoming a Data Analyst will allow me to combine my interest in technology, research, and problem-solving in a meaningful career.
I am particularly interested in learning how to collect, clean, organize, analyze, and visualize data. I want to become confident in using tools such as Excel, SQL, Power BI, and Python to turn raw data into useful insights. I also want to improve my ability to communicate findings clearly so that people without technical backgrounds can understand and use them.
Another reason I want to pursue data analysis is to improve my career opportunities and become more competitive in the job market. I want to develop practical skills that I can demonstrate through real projects and a strong portfolio.
My goal is not only to learn the technical aspects of data analysis but also to develop critical thinking, attention to detail, and responsible data-handling practices. By the end of this programme, I hope to have the confidence and practical experience needed to work on real-world data problems and contribute meaningfully to organizations that use data to make informed decisions.

My 28-Week Learning Schedule

Module 1: Foundations — Weeks 1–4

Understand data analysis and the role of a Data Analyst.

Learn basic data concepts and analytical thinking.

Set up my learning and development environment.

Learn Git and GitHub basics.

Begin documenting my learning journey.

Module 2: Excel — Weeks 5–8

Learn Excel fundamentals and data organization.

Practice formulas, functions, sorting, and filtering.

Complete practical Excel exercises and projects.

Module 3: SQL — Weeks 9–12

Learn databases and relational data concepts.

Practice SELECT, WHERE, GROUP BY, ORDER BY, and JOIN.

Learn how to clean, filter, and analyze data using SQL.

Complete SQL practice projects.

Module 4: Power BI & Data Visualization — Weeks 13–16

Learn how to import and transform data.

Create charts, dashboards, and reports.

Learn basic DAX concepts.

Practice communicating insights through visualizations.

Module 5: Python for Data Analysis — Weeks 17–20

Learn Python fundamentals.

Learn to use Pandas for data manipulation.

Practice data cleaning and exploratory data analysis.

Create visualizations using Python.

Module 6: Projects & Portfolio — Weeks 21–24

Work on real-world data analysis projects.

Practice the complete data analysis workflow.

Document project processes and findings.

Add completed projects to my GitHub portfolio.

Module 7: Career Preparation — Weeks 25–28

Improve my CV and LinkedIn profile.

Review and improve my portfolio.

Practice data analyst interview questions.

Apply my skills to real-world datasets.

Prepare for internships, freelance opportunities, and Data Analyst roles.

Potential Blockers and How I Will Handle Them

1. Limited Time

Balancing learning with my other responsibilities may be challenging. I will create a realistic weekly timetable and dedicate specific hours each week to learning and practice.

2. Difficult Topics

Some technical topics, especially SQL, Python, or advanced data analysis concepts, may be difficult to understand initially. I will break difficult topics into smaller parts, practice regularly, use reliable learning resources, and ask for help when necessary.
3. Lack of Motivation or Consistency

I may sometimes feel tired or lose motivation. I will set small weekly goals, track my progress, celebrate completed milestones, and remind myself of why I started the programme.

4. Limited Access to Resources

Some tools, datasets, or learning resources may not always be available. I will make use of free and reliable learning platforms, open datasets, documentation, and other accessible resources.

Responsible Use of AI Tools

I plan to use AI tools as learning assistants rather than as replacements for my own thinking and work. I can use AI to explain difficult concepts, provide examples, help me identify errors, and suggest ways to improve my work. However, I will follow the verify-before-use workflow by checking AI-generated information against reliable sources before accepting or using it. I will also review, test, and understand any code or answers generated by AI before including them in my projects. I will avoid presenting AI-generated work as my own without understanding it and will protect confidential or personal information when using AI tools
